# 角色体积与柔性衣物

在查看器中选择“炭治郎 · 全新制作 v3”，右侧新增“角色体积与衣物”。默认启用肢体约束和羽织约束；可以分别切换并在同一时间比较。“显示碰撞体”以青色显示近似体积，仍有肢体重叠的体积显示为红色。橙色残留读数也包含衣物表面及固定缝口。保存配置会保留当前开关。

## Review 与设计选择

[Tripo 的制作流程](https://www.tripo3d.ai/blog/gpt-6-astra-3d-character-workflow)完成的是生成、组装、绑骨和动作验收，并明确把基于物理的次级运动留作额外设置。骨骼蒙皮本身没有“不穿透”约束。当前资产由一个 Body、Hair、两枚耳饰和三块独立羽织网格组成；羽织原来只有蒙皮。

刚性/柔性应按材料和用途划分，而非让整个 GLB 使用同一种求解器：

| 部分 | 第一版处理 | 动作冲突的处理 |
| --- | --- | --- |
| 躯干、头、骨盆、上下臂、手、大小腿、足 | 15 个随骨架移动的胶囊体 | 转动关节，保持骨长；支持脚保留位置与朝向 |
| 羽织躯干及两袖 | 固定缝口 + 柔性面片 | 允许弯曲、有限弹性伸展、从身体及其他衣面让开 |
| 主发块、耳饰、贴身制服 | 继续跟随骨架 | 没有新增发丝、耳饰摆动或人体软组织模型 |

查看器只读取 MuJoCo 的记录。这里的关节修正、约束计数和残留距离属于显示层；不能解释成新增的肌肉作用、力反馈、GRF 或真实接触力。完整的三维刚体动力学必须在物理模型中另外建立。

## 求解顺序与代码

1. `HumanoidRetargeter.applyFrame` 先恢复绑定状态，执行原动作重定向和足底 IK。
2. `avatar-collision.js` 更新骨架体积，对非相邻体段作有限线段距离检测。手臂通过角度投影分离，肘屈曲上限为 155°。腿只绕髋到踝的轴调整膝盖方向，保留脚的位置与朝向。每关节的默认偏离预算为 35°；不可达时报告残留，而不拉长体段。
3. `cloth-solver.js` 采样三块衣物的当前蒙皮位置作为目标，执行 48 轮固定伪时间步的准静态约束求解。伸展边和相邻三角面的对顶点距离使用 [XPBD 的柔顺度公式](https://matthias-research.github.io/pages/publications/XPBD.pdf)；后者是弯曲近似，不是完整的二面角布料本构。所有自由节点使用相同逆质量，参数未作织物标定。
4. 身体接触包含顶点/胶囊体和三角面/胶囊体距离；能检测胶囊体从大三角面内部穿过的情况。衣物自碰撞和衣片间接触用空间哈希筛选顶点/三角面对，并按重心权重分摊位移。地面对自由衣物节点提供高度约束。
5. 衣物在临时几何副本上显示并更新法线；原 SkinnedMesh、材质、UV、权重、inverse bind、骨长和磁盘 GLB 保留。关闭衣物即恢复原蒙皮；释放模型时同时释放临时几何和碰撞辅助线框。

每次从当前蒙皮目标重新求平衡，因此正向播放、反向拖动、跨动作切换和重复暂停帧得到相同结果。浏览器缓存没有变化的暂停姿态，避免重复求解。第一版没有速度积分、重力下的自由飘动、风场和惯性。这里的 `1/60` 是求平衡使用的固定尺度，与播放器速度无关。

羽织袖根在制作时有意埋入肩部。初始化时，固定缝口在绑定姿态已经重叠的体积，只对该缝口及相邻两圈拓扑节点排除对应体积；其他区域继续检测。相邻衣面、焊接 UV 接缝、绑定时已接近的衣片缝口也作局部过滤。`seamExclusions` 记录排除的节点/体积对数，这些区域不包含在残留读数内。

手臂下垂时，躯干衣片在手臂相交区域优先向该侧肩的外侧分离，以免相邻顶点分别被最近距离投影送到肢体两侧。抬臂时改用表面法向；这是服装接触的局部方向启发式，尚非全身耦合最优化。

## Profile 配置

`collision` 是 v2 Profile 的可选字段。其他模型默认关闭，可在界面启用身体体积；独立衣物须明确指定网格，避免将皮肤、头发或身体误当布料。

```json
{
  "collision": {
    "enabled": true,
    "clothEnabled": true,
    "maxCorrectionDegrees": 35,
    "radii": { "torso": 0.06, "forearm": 0.022 },
    "garments": [
      { "mesh": "Haori_Body", "pin": { "top": 0.04 } },
      { "mesh": "Haori_Sleeve_L", "pin": { "alongChain": "leftArm", "fraction": 0.06 } },
      { "mesh": "Haori_Sleeve_R", "pin": { "alongChain": "rightArm", "fraction": 0.06 } }
    ]
  }
}
```

半径和 `nearRole` 固定区的 `radius` 以归一化后角色高度的比例表示，并不是米。身体包络是按骨架比例建立的可调近似，尚未从 Body 网格拟合。`radii` 可配置 torso、pelvis、head、upperArm、forearm、hand、thigh、shin、foot。需要用线框核对特定角色的粗细。

衣物支持三种固定方式，只能选择一种：`top` 固定绑定网格最上方的高度比例；`alongChain/fraction` 固定沿指定肢体轴最靠近根部的一段；`nearRole/radius` 固定绑定姿态靠近某个标准骨骼角色的节点。必须同时选中固定节点和自由节点。

每块衣物还可设置 `stretchCompliance`（默认 `2e-7`）、`bendCompliance`（`2e-4`）与 `attachmentCompliance`（`8e-5`）；数值越大，越容易偏离对应约束。采用统一逆质量和固定求解尺度，这些值不是实测织物参数。每块衣物上限 4096 个输入顶点，最多 8 块；不支持衣物 morph target。重复网格名、无效角色、非有限参数等会拒绝导入。

Tanjiro 的制作源 Profile 和查看器 Profile 已同步；重新运行 `publish-local.py` 会保留碰撞配置。GLB 内容和摘要未因这一功能改变。

## 诊断与当前边界

身体报告修正前/后的重叠数、最大穿透、最大角度修正和未解决的体段对。衣物分别报告自由顶点、三角面、固定缝口及衣物自接触的残留，面板取这些距离的最大值，不用顶点检测通过来代替整片衣面通过。最大局部伸长与固定缝口残留也显示在读数的悬浮提示中。

不相容接触不能以拉裂衣片来“解决”。每块衣片的最终位移还有形变预算：节点偏离蒙皮目标不超过角色高度的 6%；每条伸展边不超过绑定长度的 1.5 倍，或输入蒙皮已存在长度的 1.05 倍（取较大者）。超过预算会把该衣片的修正缩回目标，保留固定缝口，并在界面显示达到形变上限的衣片数。残留接触在这一保护之后重新测量，因此不会把保护前的较小数值当成最终结果。

这是一版可检查的接触原型，尚不能保证任意姿态无穿透。衣物固定约束、原网格的袖口/肩部结构、近似身体包络及有限迭代可能互相冲突；抬臂时尤其可能残留局部穿透与较大局部拉伸。刚体关节预算、固定足底也可能使某些体段对不可分离。必须查看残留读数、具体姿态和外形，不能把“测试通过”理解为所有衣面接触都归零。

衣片自碰撞为离散的顶点/三角面约束，未包含连续碰撞、完整边/边约束及拓扑保持；快速跨帧、细长三角面或整片翻面仍可能漏碰。准静态 CPU 求解的成本也明显高于原蒙皮，播放帧率取决于设备。下一步应先标定包络、修整真实缝口/袖孔和改善约束收敛，再引入低分辨率布料笼、后台求解和真正的固定步长惯性模拟。

## 回归验证

`test/avatar-collision.test.ts` 覆盖有限胶囊体、退化与相切情况、穿过三角面内部的胶囊体、故意穿过躯干的前臂、有限修正预算、柔顺度差异、衣物绕体积变形、固定缝口、关闭与释放恢复。实际 Tanjiro 在本地存在时还验证九个动作的中间/终点采样、往返 seek、一致的足底位置、骨长与比例，以及源 GLB、几何、权重、材质、inverse bind、动作输入的不变性；本地模型缺失时显式跳过这项资产测试，通用用例仍运行。

```sh
npm run typecheck
npm test
npm run web
```
